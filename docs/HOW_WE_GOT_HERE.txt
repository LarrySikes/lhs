WHERE YOU STARTED  (~/src/iwai_project/)
--------------------------------------------------------------------

Two text files (Aug 22):

  doc.txt       — Product vision: IWAI / “universal compute”
  workplan.txt  — How to build it as a company + compiler platform

The ORIGINAL idea was NOT “replace Python/Rust with a new app language.”

It was:

  A SMALL COMPUTE LANGUAGE (kernels / tensors / matmul / parallel)
       +
  Aggressive optimizer that picks CPU/GPU/NPU implementations
       +
  Profiler that explains bottlenecks
       +
  Autotuning + performance database (the moat)
       +
  Sell PERFORMANCE PORTABILITY to enterprises / hardware vendors
       (not “cool syntax”)

Workplan name for that: UCC (Universal Compute Compiler).

Key decisions in those notes:
  - Do NOT rebuild all of LLVM — sit above MLIR/LLVM
  - Accept Python/C++/etc.; language is the interface, product is speed
  - Year-1 niche: inference / numerical kernels, NVIDIA first
  - Alternative path also mentioned: SQL/data compiler

--------------------------------------------------------------------
HOW WE DIVERTED TO LHS  (~/src/newproj/)
--------------------------------------------------------------------

Later (Sep 19–21 chats), while working on IWBasic day_planner /
iwbc, you asked a “crazy question”:

  Could we address the TWO-LANGUAGE PROBLEM —
  Python ease + Rust/C safety/performance —
  using iwbc as a PROCESS template (not BASIC syntax)?

That is a DIFFERENT product from IWAI:

  IWAI  =  compute kernels + heterogeneous optimization (narrow DSL)
  LHS   =  general-purpose app language + toolchain (lhsc)

We discussed BOTH. You then chose to explore the general-purpose
path “from scratch” in ~/src/newproj, named it LHS, and we shipped
an MVP (parser, checker, run/build, Cranelift subset, day_planner CLI).

So: not a wrong turn — a fork in the conversation.
The IWAI notes were never deleted; they are still the compute/UCC plan.
